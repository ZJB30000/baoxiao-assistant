# 设计说明

> 完整版（含表格与排版）见 [04-设计方案.docx](04-设计方案.docx)。

## 一、设计目标

把 AI 放在“结构化、建议、台账”三个位置，把人力留在“现场处置、专业签核、复查结论”三个位置。目标是复发率 34% → 15%，整改闭环 10 天 → 5 天，10 店试点归类一致率 ≥ 95%，重大问题漏报为零。

## 二、边界

| 做 | 不做 |
| --- | --- |
| 证据结构化、归类建议、培训建议 | 自动扣罚、自动发布合格结论 |
| 复查提醒、审计归档、周复盘台账 | 替代现场处置、替代复查结论、替代专业签核 |

## 三、架构分层

```text
数据层  ── 巡店系统 / 培训平台 / 门店档案（只读）
            └ 字段校验：业务编号、事件时间、版本
            └ 断连：带时间戳只读快照 + 编号去重 + 待刷新标识
智能层  ── 证据结构化 → 归类建议（含置信度）→ 培训建议
            └ 低置信 / 歧义 → 人工修复队列（不入自动样本）
业务层  ── 督导签收 · 协调员核对 · 质量经理签核 · 店长复查
审计层  ── 编号 / 版本 / 事实引用 / 建议结果 / 人工改动 / 签核人
```

## 五、关键实现

- 规则版本化：`src/my_tool/core/rules.py`，升版不删旧版，历史建议可按当时版本重建。
- 转人工判定：`src/my_tool/core/classifier.py`，四类情形必须人工——资料缺少依据、版本冲突、能力未验证、系统不可用。
- 字段校验：`src/my_tool/utils/validators.py`，对应业务编号、事件时间、版本字段。
- 默认参数：`config/default.yaml`，含更新频率 60 分钟、待刷新 120 分钟、留存 90 天。

## 六、验收与停止条件

- 各岗完成时间分开记录，固定分母、排除规则与统计周期。
- 触发停止条件（漏报、以照片代替复查）立即暂停试点并复盘。
- 指标为目标值，不作为合同承诺。
